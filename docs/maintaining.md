# Maintainer guide

Read [support](../SUPPORT.md), [contributing](../CONTRIBUTING.md) and
[security](../SECURITY.md) for the public policy. The public maintainer identity and
reporting route remain unconfirmed in this private candidate.

## Triage and review

Reproduce bugs with synthetic data and the exact reported commit. Keep private
reports out of public issues; acknowledge uncertainty when logs or provider billing
are unavailable. Review the diff and tests, including workflow/permission changes,
before accepting a green check. Review code generated by agents as untrusted input.
Require the current-head contributor checks and an independent human review; keep
merge authority with humans and review governance changes separately.

For dependency upgrades, inspect lockfile changes, advisory IDs, direct/transitive
and runtime/development scope, vendor terms and exact installed versions. Do not
run blanket audit fixes or silently change model IDs. SDK upgrades need compatibility
checks and the worker boundary suite. Preserve vendor notices and inventory any
new copied source. Re-audit every lockfile before each release; an advisory is release
work until mitigated or explicitly evaluated in the release decision.

## Operate the local profile

Use [run controls](run-controls.md) for status, cancellation, estimates and retention;
[recovery](recovery.md) for quarantine/replay; and
[local runtime](local-runtime.md#backup-restore-and-reset) for database backups.
Inspect uncertain effects before retrying. Paid jobs need fresh human activation;
recovery is not permission to spend again. Stop the runtime before a recovery cutover,
preserve needed evidence and recheck GitHub authorization/protection afterward.

A code upgrade is not a database rollback strategy. Back up the current database,
retain the prior source/image/configuration privately, review migrations, rebuild
and run the migrator using the same Compose project/profile. Migrations are
forward-only and checksum-checked. Verify readiness, durable state and affected
integration paths before resuming live work. If a migration or check fails, stop
processing and restore into a new verified database; reconcile external effects.
Do not edit migration checksums or drop a working database to hide an upgrade error.

## Prepare a release

1. Freeze a full source commit and update release notes, support versions and known
   limits. Re-run contributor checks and the affected runtime/worker exercises at
   that commit; review results rather than relying on an old green workflow.
2. Verify the quickstart from a clean directory and have an independent operator
   complete onboarding/recovery. Record interventions and fix blockers.
3. Confirm ownership, license, required attribution and the exact distribution
   contents. Project source licensing does not license vendor binaries/services.
   Resolve the documented dependency/security findings before distribution.
4. Build the [source artifact](contributor-ci.md#deterministic-source-artifact) twice,
   compare bytes/hashes, review its file manifest, and scan source plus reachable
   history for secrets and unintended internal material. Keep private review records
   outside public artifacts. Container images are not byte-reproducible artifacts.
5. Confirm the destination, named maintainer and real reporting channels. Enable and
   test private vulnerability reporting, set required `contributor-ci` protection,
   and inspect fork workflow permissions. Verify all public links after provisioning.
6. Obtain the owner's approval of the concrete commit, artifact hashes, license,
   destination and known limits before tagging/publishing. Publish only that reviewed
   artifact. Do not upload local dependency trees, secrets, backups or vendor images.
7. After publication, verify the downloadable bytes and clean setup, and triage
   reports within the stated best-effort scope. Announcements and external invitations
   require their own authorized communication.

The source builder does not grant publication approval. Keep release notes truthful
about manual steps, incomplete coverage and provider/account constraints.
